# VisionPro to AMV API mapping

For each class, property, method and enumeration of the public VisionPro .NET API that AMV covers, this table gives the AMV counterpart, every departure, and what is not provided. Each section says which of its names were checked against the public VisionPro .NET reference (names, signatures and, where stated, defaults only; no text was copied). The rows a section marks as not checked (some transform rows, the exceptions named after a situation) were written from general knowledge of the API; verify them before relying on them.

General rules (see `docs/DESIGN.md` section 3):

* The `Cog` prefix (and `ICog` for interfaces) becomes `Ks`: `CogBlobTool` -> `Ks_Blob_Tool`, `ICogTool` -> `Ks_Tool`. Interfaces become tagged types: abstract ones (`Ks_Tool`, `Ks_Image`, `Ks_Shape`, `Ks_Region`) and, for value types, concrete ones (`Ks_Run_Status`).
* CamelCase becomes Ada_Case; acronyms (PM, CNL, IP, ID, RMS) stay together.
* Enumeration literals that are Ada reserved words get `_` plus the last noun of the type name.

## Coordinate space trees (AMV.Coordinate_Spaces)

The VisionPro names and signatures in this section were checked against the public VisionPro reference. Every space stores the transform that maps its coordinates into its parent's (Parent_From_Child), exactly as given, as VisionPro's `AddSpace` takes it (parentFromNew). ## Images and image files

The Ada names of `AMV.Images` did not change when the package moved onto the SPARK kernel `AMV.Kernels.Images`. Its C functions are `ks_image_8_grey_*` and `ks_image_16_grey_*` (an opaque handle per image: create, destroy, width, height, get_pixel, set_pixel, fill, duplicate, get_row, set_row), `ks_image_24_planar_color_*` (a colour image is three 8-bit handles: create, get_pixel, set_pixel, set_plane, duplicate) and `ks_image_*` for the coordinate space state (selected_space_name, set_selected_space_name, resolve_space_name, get_transform, selection_for_new_tree, set_pixel_from_root_transform), in `include/amv.h`.

## Pattern location (AMV.PM_Align)

The logic lives in the SPARK kernel `AMV.Kernels.PM_Align` (with the private children `Poses`, `Pyramids`, `Training`, `Search` and `Refinement`); the C functions are `ks_pm_align_*` in `include/amv_pm_align.h`. Clean room: PatMax and PatQuick are Cognex's own algorithms; AMV implements its own method from public literature (gradient-direction shape matching with Steger's similarity measure on a coarse-to-fine pyramid, then least squares on sub-pixel edge points), and the codes PatMax and PatQuick name AMV's two variants of it, not Cognex's algorithms. VisionPro publishes no defaults for most properties; the defaults are AMV's. The run parameter and zone records are the kernel's C records (`Int32` codes; `AMV.PM_Align.Code` converts); the pattern is a private type that keeps the train image, region and Origin in Ada and the train parameters and the model in a kernel handle.

## Tool group and tool block (AMV.Tool_Group, AMV.Tool_Block)

Every decision of a group lives in the SPARK kernel `AMV.Kernels.Tool_Group`: the member list (members are 64-bit keys; the Ada API uses the tools' addresses), the disabled flags, AbortRunOnToolFailure, the order of a run and when it stops, the run's result and message (through a cursor: `ks_tool_group_run_begin`, `_run_next`, `_run_report`, `_run_end`), and the terminal tables of a block with their scalar values. The Ada API only dispatches `Run` on the members and keeps the objects (member accesses, image, transform and shape values) in the kernel's order. The C functions are `ks_tool_group_*` and `ks_tool_block_terminals_*` in `include/amv_tool_group.h`. The class, property and method names were checked against the VisionPro 9.23 .NET reference (names and signatures only); rows marked "(AMV name)" have no VisionPro counterpart. The reference gives neither the default of AbortRunOnToolFailure nor which results count as a tool failure: both are AMV's choices (False; only Error). Streams are not provided: a group refers to user-declared tools by access, which a stream cannot keep ('Write and 'Read of a group, a block or a terminal collection raise Program_Error).
