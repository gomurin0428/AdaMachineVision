# Independent Lean camera specifications

This package compares separately authored Lean models with selected SPARK contracts on the current Ada sources. It covers the lifecycle operations `Open`, `Start`, `Stop`, `Close`, `Is_Open`, and `Is_Streaming`, plus the acquisition contract relations for `Grab` and `Build_Frame`. The models are authored separately from the generated Ada comparison modules.

## Reproduce

The local installer below is the official Elan installation command documented at <https://github.com/leanprover/elan#installation>:

```sh
curl https://elan.lean-lang.org/elan-init.sh -sSf | sh -s -- -y --no-modify-path --default-toolchain none
export PATH="$HOME/.elan/bin:$PATH"
elan toolchain install leanprover/lean4:v4.19.0
```

The `lean-toolchain` file pins Lean and Lake to `leanprover/lean4:v4.19.0`. The Lake project has no external package dependencies and uses only Lean core/Std; it does not require Mathlib.

The compiler-backed `Pixel_At` tests and freshness check also require GNAT-FSF 16.1.0-1 for Linux x86_64 (`x86_64-pc-linux-gnu`). Install the pinned upstream archive and verify its published SHA-256 before extraction:

```sh
set -eu
toolchain="$HOME/.local/share/amv-toolchain"
release="gnat-16.1.0-1"
asset="gnat-x86_64-linux-16.1.0-1.tar.gz"
base="https://github.com/alire-project/GNAT-FSF-builds/releases/download"
tmp="$(mktemp -d)"
trap 'rm -rf "$tmp"' EXIT
mkdir -p "$toolchain"
curl --retry 3 -fsSL -o "$tmp/$asset" "$base/$release/$asset"
curl --retry 3 -fsSL -o "$tmp/$asset.sha256" "$base/$release/$asset.sha256"
expected="$(cut -c1-64 "$tmp/$asset.sha256")"
(cd "$tmp" && printf '%s  %s\n' "$expected" "$asset" | sha256sum -c -)
tar -xzf "$tmp/$asset" -C "$toolchain"
export PATH="$toolchain/gnat-x86_64-linux-16.1.0-1/bin:$PATH"
test "$(gcc --version | sed -n '1p')" = "gcc (GNAT-FSF-builds) 16.1.0"
test "$(gcc -dumpmachine)" = "x86_64-pc-linux-gnu"
```

From this directory:

```sh
export PATH="$HOME/.local/share/amv-toolchain/gnat-x86_64-linux-16.1.0-1/bin:$HOME/.elan/bin:$PATH"
python3 tools/extract_contracts.py --check
python3 tools/extract_grab_contracts.py --check
python3 -m unittest discover -s tests -v
lake build CameraLifecycle
python3 tools/check_axioms.py
```

The focused workflow is `.github/workflows/lean-camera.yml`. It checks both generated comparison modules, runs the Python parser and source-mutation tests, builds the Lean proofs, and audits proof axioms. The Grab extractor reads the three Aravis Ada specifications plus `src/amv-kernels-images.ads` and `src/amv-kernels.ads`.

## Source translation and proof boundary

`tools/extract_contracts.py` is a deliberately small Python-standard-library tokenizer, recursive-descent expression parser, type checker, and Lean emitter. It reads the three Ada specifications directly at the checked-out paths. It validates the selected enum domains, `T`/`N` aliases, formal names/types/modes, exact selected Pre/Post presence, allowed calls, and full consumption of every selected expression. Unsupported tokens, operators, calls, clauses, aliases, domains, or signatures fail extraction. `--check` compares the generated source text with `CameraLifecycle/Generated.lean`; a hash match alone is not accepted as agreement.

For the lifecycle specification, the only generated logic is `CameraLifecycle/Generated.lean`. `CameraLifecycle/Model.lean` is authored separately from the state-machine requirements. `CameraLifecycle/Proofs.lean` proves equality of each helper and equivalence of each full allowed transition relation in both directions, including all selected preconditions and postconditions. The relation quantifies over arbitrary `Nat` handle identities. `0` represents null; handles are only compared, never dereferenced. The Grab comparison is generated separately in `CameraLifecycle/Grab/Generated.lean` and checked against the authored model and proofs under `CameraLifecycle/Grab/`.

`Device_ID` is abstracted to a `selectorValid : Bool` input only at approved `Valid_Selector`, `Open_Status`, and `Open_State` arguments. The extractor validates `Valid_Selector`'s `String`-to-`Boolean` profile and rejects any aspects, but does not translate its string body; the string predicate itself is not claimed. `Camera_Result` is accepted only as exactly `Camera_Result (Result)`, once in each of `Open_Status`, `Start_Status`, and `Stop_Status`, and nowhere else, including preconditions. Generated call-path guards therefore account for the actual restricted call argument and prove that each call satisfies `Camera_Result`'s precondition excluding `Native_Not_Called`.

The lifecycle trusted translation boundary is the tokenizer/parser/type checker and its explicit supported expression subset, including `Old`/`Result` attributes. The handle model's `Nat` identity, null `0`, non-null test, and preservation-by-equality are abstraction assumptions; these theorems do not establish native `Address` semantics or actual pointer behavior.

## Grab and frame-contract scope

`tools/extract_grab_contracts.py` is a separate, fail-closed Python-standard-library extractor for the actual `Grab` Pre/Post, `Build_Frame` Post, and the expression dependencies `Grab_Status`, `Pixel_At`, `Valid_Observation`, and the 8-bit `Valid_Image` overload. It validates the selected enum and record domains, aliases, helper/operation profiles and modes, array/access/image type declarations, integer ranges, relevant constants, overload set, and exact selected aspects. It translates every selected expression into `Grab/Generated.lean`; unsupported or trailing syntax, types, attributes, calls, profiles, or additional selected contract aspects fail extraction. The independent model is in `Grab/Model.lean`; `Grab/Proofs.lean` proves helper agreement and iff agreement for the complete bounded `Grab` and `Build_Frame` relations, including their respective pre/post constraints.

The model spells out all ten frame statuses and preserves source precedence: non-streaming or zero timeout, acquisition outcomes, buffer timeout/failure, payload and Mono8 format, positive dimensions, the strict `width * height > 2^31 - 1` limit, then byte/source length and pointer/bounds checks. Exactly `2^31 - 1` pixels is not classified as too large. `Grab` retains its handle/state precondition, valid-observation and acquisition-dispatch clauses, all nine canonical observation fields when acquisition is not called, success-to-out-of-memory status allowance, image dimensions, and every universal pixel equality. Non-success requires a null image. `Build_Frame` is modeled only with its own Post; it is not strengthened with Grab's precondition, dispatch, observation-validity, or canonical-output clauses.

Frame bytes and image/pixel pointers are explicit nullable options. Non-null byte arrays and matrices have explicit first/last bounds and arbitrary content functions with `UInt8` values; the model does not enumerate sample images or restrict pixel contents. The 8-bit image invariant includes both pointer null checks, positive dimensions, zero first row/column, and last bounds equal to dimension minus one. `Pixel_At` keeps its fallback guards and its actual row-major byte access `Y * Width + X + 1`; the success-pixel corollaries connect arbitrary valid output pixels to that byte content.

The bounded domains are explicit: `Int32` and `Int64` use their validated signed ranges; `Unsigned_32` and `Unsigned_64` use `0 .. 2^32-1` and `0 .. 2^64-1`; `Pixel`/`Grey_8` values are Lean `UInt8`; and `Natural`, `Positive`, and `Integer` use the supported GNAT target assumption that Standard `Integer` is 32-bit and `Natural` is `0 .. 2^31-1`. The byte-array and matrix bounds are represented independently, including nullable arrays. Before emission, the extractor type-checks selected expression trees and performs conservative interval and path-condition analysis for casts and signed/Standard-integer `+`, `-`, and `*` intermediates. It erases an integral conversion only when the input is proven to fit the target range on that evaluation path: for example, positive dimensions precede `Natural` casts, the maximum-pixel branch bounds the `Unsigned_64` product cast, and the strict byte-count guard bounds the row offset before its `Natural` conversion and `+ 1`. It preserves `and then`/`or else` evaluation paths and prior-false `elsif` conditions; eager `and`/`or` do not supply short-circuit range facts. Unproved conversions, overflow-capable intermediates, modular arithmetic, and wrapping unsigned conversions are rejected. This static range analysis is part of the trusted extractor, not a kernel-proved fact. These are mathematical contract-domain assumptions, not claims about unbounded Ada arithmetic.

The acquisition extractor's trusted boundary is its strict tokenizer, expression parser, profile/domain validator, and emitter for the selected comparisons, arithmetic, Boolean operators, membership, casts, record fields, array bounds/access, `if`/`elsif` (including the contract's implicit `True` else), approved helper calls, and nested `for all` ranges. It uses predefined operators only and rejects local operator overloads and contract pragmas rather than silently changing or omitting their meaning. The Lean theorems establish source-contract agreement over the stated bounded mathematical domains. They do **not** prove procedure bodies, allocation or pointer validity, array storage, absence of compiler/runtime errors, native `Address` or C/Aravis semantics, Aravis internals, GigE Vision protocol behavior, physical cameras, or total C-memory correctness. They make no `Global`/`Depends` agreement claim; the existing selector and opaque-handle abstractions remain unchanged. Temporary-source mutation tests regenerate from edited Ada and require semantic changes to fail in the Lean proof module, rather than relying on source hashes.

## Compiler-backed `Pixel_At` pilot

`tools/extract_pixel_compiler.py` is a separate GNAT-backed path. It never imports or uses `extract_grab_contracts.py` as evidence. It compiles the unchanged `optional/aravis/src/amv-spec-gige_vision.ads` and its actual type dependency with GNAT-FSF GCC 16.1.0 for `x86_64-pc-linux-gnu`, at `-O0` and without `-gnatn`, using `-gnat2022 -gnatW8 -ffp-contract=off -gnatwa -gnatVa` and the verification-only configuration file. `-fdump-tree-original-raw` supplies GCC's resolved expression and check nodes; companion `-gnatG -gnatL` output supplies compiler-expanded check predicates and source-line mapping; `-gnatS` supplies Standard subtype bounds. The importer starts at the compiler-selected final `array_ref`, derives its index and row temporary from that node, links the preceding Natural and array-index checks and nested increment-overflow branch, and records their actual GCC node IDs. It validates every imported scalar operation/conversion's resolved type and numeric representation, including signedness, precision, size, and bounds. Natural's subtype range comes from compiler Standard output and the expanded Natural check, not from its GCC base integer type or size. The generated artifact records compiler version/target, normalized switches and include roots, the exact verification-policy text and SHA-256, selected node IDs, and diagnostic source location. Unknown or ambiguous nodes, types, checks, signatures, predicates, compiler versions or targets fail extraction. The build and diagnostics are disposable; `--diagnostics-dir` preserves raw compiler outputs when requested.

The compiler probe uses `tools/ghost-check.adc`, a verification-only assertion-policy override that sets `Ghost => Check` (and applicable assertion policies to `Check`) so the actual Ghost function is emitted. Production `contracts.adc` is not changed and keeps the production policy. Consequently the artifact records the source/compiler semantics under this explicit verification policy; it is not a claim that production executes the Ghost expression. The generated artifact retains the selected raw GCC tree and compiler runtime-check calls, plus Lean-interpreted Natural-range, increment-overflow, Positive-conversion and array-index predicates validated against compiler outputs. Its importer is trusted, version-specific glue; Lean proves the imported scalar/check interpreter, not the correctness of GNAT's front end, its raw-tree format, or the importer itself. The current extraction step hardens selected-return/control-path provenance but is not claimed as a final general-purpose Ada importer.

`Grab/CompilerIR.lean` defines typed bounded scalar operations and distinct range, overflow, Natural-conversion, increment, Positive-conversion and array-index failures. `Grab/CompilerProofs.lean` proves the generated widened row and compiler-derived index-outcome interpreter agree with an independently authored mathematical model for all representable `x, y : Natural`, `width : Int32`, and abstract array lower/upper bounds, including the modeled range/overflow/index failures—not samples or only successful pixels. `compiler_widened_row_eval` proves the selected Int64 casts, multiplication and addition succeed throughout those input bounds. A type-changing GCC `nop_expr` is conservatively represented as a Lean checked cast rather than erased; the generated bounds feed `evalScalar`, and the proof establishes that these additional checks succeed on the imported path. The Natural-range check is interpreted before narrowing, the overflow check precedes increment and Positive conversion, and `compiler_generated_finish_predicates_match` proves the actual returned index expression and array-index predicate share the same normalized subexpression. `compiler_index_backend_cast_safe` proves the successful result also fits the compiler's unsigned 64-bit array-index representation. Invalid/uninitialized bit patterns remain outside the abstract well-typed input domain, and the byte-array view is an abstract valid view rather than a native-memory proof.

## Compiler-backed frame-size suffix

`tools/extract_frame_size_compiler.py` separately compiles the unchanged `Grab_Status` Ghost function and imports only its ordered suffix at `amv-spec-gige_vision.ads:129–147`: invalid dimensions, strict `Width * Height > Max_Image_Pixels`, the ordered received-size disjunction, and success. It uses the pinned Linux GNAT-FSF GCC 16.1.0 target `x86_64-pc-linux-gnu` and the verification-only `Ghost => Check` policy; `--check` is the freshness command. The importer selects `___ghost_amv__spec__gige_vision__grab_status` from GNAT's raw tree, validates direct frame fields, resolved subtype/representation bounds, casts, status codes, return-path order, array descriptor path, runtime checks, and companion expanded output. It fails closed on unrecognized tree shapes or checks. It does not use `extract_grab_contracts.py` as compiler evidence.

`Grab/FrameSizeGenerated.lean` contains typed expression, ordered control-flow, runtime-check, resolved-type, compiler, policy, and provenance IR derived from that compilation. `Grab/FrameSizeIR.lean` evaluates casts and arithmetic with distinct range, overflow, access, and invalid-data outcomes and preserves short-circuiting. `Grab/FrameSizeProofs.lean` states an independently authored four-status suffix and the bounded observation-domain obligations; it does not assume `Valid_Observation` or consistency between source size, count, nullness, or byte bounds. The byte-array view is still an abstract model, not a proof of native memory validity. The guarded bridge to `Model.grabStatus` assumes the earlier streaming, nonzero bounded timeout, acquisition-success, buffer-success, image-payload, and Mono8 prefix. This is not a claim of whole-function GNAT/GCC control-flow equivalence and does not cover `Acquire`, the C boundary, or Aravis internals.

From `verification/lean-camera`, regenerate or check the compiler artifact with `python3 tools/extract_frame_size_compiler.py --check`; run `python3 -m unittest discover -s tests`, `lake build CameraLifecycle`, and `python3 tools/check_axioms.py` for the test/build/audit path. The workflow runs the frame-size freshness check alongside the existing Pixel_At and contract freshness checks.

`compiler_frame_size_suffix_agrees` proves that the evaluator returns the independent four-status suffix for every `observationDomain` frame. It runs the compiler-generated `.control` tree; the embedded GNAT range, invalid-data, and access-check actions execute at their imported expression positions and preserve short-circuit order. In particular, absent byte views stop at the null guard before `First` or `Length` is read, while present views prove those accesses safe.

The evaluator also checks target bounds conservatively while interpreting normalized typed casts and arithmetic; these evaluator-side checks are distinct from the compiler-derived `.check` actions. The proofs show they succeed on the declared domain: all Int32 products fit Int64, the guarded positive-dimension product is nonnegative, `Source_Size` fits its unsigned-64 representation, `Byte_Count` widens safely to Int64, and present-view `Size`, `Integer`, and Int64 casts plus length subtraction/addition stay in range. Reversed permitted bounds take the compiler-derived zero-length branch. These results do not strengthen `observationDomain` to require `Valid_Observation`, a first bound of 1, or size/count consistency, and they do not prove native array-memory safety.

The model-guard integration is verified in Lean and included in the exact no-axiom audit. `compiler_pixel_read_branch_avoids_index_failures` proves, under `observationDomain`, positive dimensions and byte count, a present byte view with first bound 1 and length equal to `byteCount`, in-range coordinates, and the strict `row < byteCount` guard, that the compiler-index interpreter returns the row-major index value and `Model.pixelAt` reads the corresponding byte. Separate fallback theorems prove that `Model.pixelAt` returns zero under its explicit early-guard, invalid-coordinate, and row-outside-byte-count guard assumptions. These results cover the independent Lean model and guarded bridge only: they do not establish whether GNAT evaluated the Ghost expression, equate a model fallback with a scalar-IR failure, or prove GNAT/GCC control-flow equivalence for the whole `Pixel_At` function. Raw scalar/index outcomes retain distinct failure kinds.

This is a Linux-only verification pilot using GNAT-FSF GCC 16.1.0 for `x86_64-pc-linux-gnu` and the recorded verification-only `Ghost => Check` policy; production flags and `contracts.adc` are unchanged. It does **not** establish GNAT front-end correctness, optimizer/backend correctness, machine-code or whole-function control-flow equivalence, native memory safety, C/Aravis or protocol semantics, hardware behavior, or any camera/video behavior. The observed `Build_Frame` dump is not used to claim unrestricted negative-width equivalence: its optimized lower-bound check is absent in that guarded context. CI checks the complete selected Ada source dependency trees, compiler freshness and compiler-backed source mutations, then builds and audits the proofs.
